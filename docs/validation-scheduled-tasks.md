# 本机定时任务随账户切换与运行历史清理

日期：2026-11-02。对应版本：v0.1.5（build 7）。

对应 [issue #1](https://github.com/Chiiz0/Sync-Claude/issues/1) 与 [issue #2](https://github.com/Chiiz0/Sync-Claude/issues/2)。任务同步属于原有切换、同步并重载和首次保存账号流程；无需先清理源账户目录。

## 适配依据

- 只读检查本机 Claude Desktop 4.4212.0 的 app.asar：本机 Code 的任务登记位于各账户/组织 `claude-code-sessions` 下的 `scheduled-tasks.json`；提示词使用同一系统用户的 `.claude/scheduled-tasks/<id>/SKILL.md`。调度器按当前账户/组织加载一个登记文件。
- 实际 schema 含任务 ID、共享提示词路径、工作目录、cron/单次时间、启用状态、模型、`lastRunAt`、`lastScheduledFor`、`missedRunScanFloor`、通知引用、跳过记录与可选重试状态。提示词前置元数据也可指定模型，需要一并检查。
- 本机旧调研缓存的任务 schema 也包含上述时间字段；没有把结构 fixture 当作真实旧客户端执行验收。
- [Anthropic 定时任务文档](https://code.claude.com/docs/en/desktop-scheduled-tasks)区分本机与云端任务、暂停与删除任务、运行会话及错过调度后的补跑。当前网页会随版本变化；本次磁盘写入适配以本机客户端格式为准。

## 实现与一致性

- 保留任务 ID、共享提示词文件、启用/暂停状态与运行关联。为旧版本已导入但丢失关联的会话补回 `scheduledTaskId`，不改写其标题、模型或账户内授权。
- 任务定义、会话、模式/登录与任务索引使用同一个写入前事务，失败全部回滚；崩溃后复用恢复日志。共享提示词不移动、不删除；同步前验证格式、工作目录和内容指纹。
- 按每个副本的同步基线合并任务定义。单侧修改继续传播；多侧不同修改、不同任务同名或同 ID 冲突不自动覆盖。目标已有授权留在目标，新导入任务使用默认权限，不把旧审批当作新账户授权。
- 时间状态取各副本与共享索引中的最新值；跳过记录去重并合并。首次导入目标时设置原生扫描起点；启用且已到期的单次任务、待重试任务须先处理。只保留一个稳定任务 ID，不通过删除源任务解决重复调度。
- 删除识别仅针对此前已跟踪的活动账户中的完整登记文件。缺少整个文件/目录不推断删除；第一次跟踪前的历史删除无法判断。已确认移除的任务写入删除决定，切换和目录恢复不会复活它。
- 清理旧账户前检查当前账户的任务定义、调度时间、跳过记录及共享提示词完整性；未同步修改、缺少提示词、待重试状态仍阻止清理。
- 运行历史移除需要用户选择并确认，且正文有明确结束事件、无已知等待/中断状态、没有 Code 会话进程。保守地阻止全部运行清理，直到进程检查可确认安全；不会仅凭轮次数或归档标志删除。
- 所选运行的所有账户副本写入删除标记，通知引用被解除，任务及其调度不变。正文永久清理是独立步骤，继续复用共享正文保护、范围复核和中断续做。

## 隔离回归

使用临时 home 和 FakeProcess，不操作真实登录、任务、会话或提示词。覆盖：

1. 两个已保存官方账户 A → B → A → B，启用/暂停状态、修改与最近调度时间连续保留；重复同步不重复任务。
2. 会话任务关联、通知引用、旧导入记录补链、提示词内容保持、目标授权隔离。
3. 并发修改、同 ID/同名冲突、未知字段、远程任务、缺少提示词、非法提示词、符号链接、无唯一目标目录、待重试、API 模型及提示词内模型不兼容的原子失败。
4. 跳过记录合并、调度时间不倒退、已到期单次任务不意外补跑、未来/暂停单次任务保持原状态。
5. 活动账户任务移除传播、整个登记文件缺失不算删除、恢复旧目录不复活、删除与其他修改冲突时保护内容。
6. 事务崩溃恢复、首次保存新账户自动同步、任务完整保留后的旧目录清理资格。
7. 运行历史单独移除及正文永久清理、共享正文保护、其他运行保持、进程/审批/中断/不完整正文保护、过期预览复核、失败后删除决定回滚。
8. 清理通知引用时不吞掉其他账户尚未同步的任务修改。
