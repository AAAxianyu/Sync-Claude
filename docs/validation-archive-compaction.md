# 旧正文归档兼容修复验证

日期：2026-11-10。基于 PR [#3](https://github.com/Chiiz0/Sync-Claude/pull/3)，审阅提交 `bb1a5fa8a4798fb917495dd05818b4fb16bde7d8`。

## 审阅结论

PR 的哈希验证、严格前缀回收和开关持久化方向正确；原有 159 项测试通过。旧版存量维护还存在两个缺口，已在本地补丁修复：

1. 迁移只在 `ingest()` 成功读取当前记录、写入新快照后执行。关闭后台归档、当前记录损坏，或没有空间再写一个完整快照时，存量副本无法独立回收。
2. 全局一次性标记加上“仅新快照写入后精简”的条件，会漏掉旧版本后来补写/恢复的副本，以及新快照已写入但精简中断的目录。

## 补丁行为

- `Engine.compactHistory()` 只维护工具自身的正文归档，不依赖 Claude 当前记录，不生成新快照，不停止 Claude。界面启动、刷新和后台轮询都会调用，独立于“后台归档”开关；另提供 `--compact-history`。
- `ingest()` 在读取当前数据和分配新正文快照前先维护存量，写入后再次检查。
- 不再用 `transcript-compaction.json` 作为永久完成门槛。每轮检查归档清单；本进程只跳过文件名、大小、时间和 inode 未变的目录，重启后重新校验。
- 每个目录独立处理，失败保留提示并重试，其他目录继续回收。显示本轮删除份数及文件字节总量；字节总量不保证等于 APFS 实际释放的物理块数。
- 哈希和前缀按 1 MiB 分块读取，内存不随保留的正文分支总量增长。仅以哈希有效的更长快照作为证据；删除前重新检查文件状态。
- 保留分叉、未知命名/哈希不符文件、所有 `records/` 元数据、原生正文及账号数据。拒绝符号链接。沿用操作锁，待恢复/清理操作时不执行，清理预览期间暂停界面后台维护。
